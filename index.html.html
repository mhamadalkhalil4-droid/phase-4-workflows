2Payer Correction Loop

3Title Mismatch — Two-Stage Correction (RR05)
Actors: System · Payer · Bank  ·  Screens: SCR-PAY-004 Standard and Extended
⚙️ Threshold is 2 total bank submissions on the mandate regardless of rejection reason.
Standard stage: payer provides account holder name (text entry only — must match bank account exactly).
Extended stage: name + IBAN confirmation (pre-filled from original entry, editable). No EID re-scan in either stage.

8Signature Issues — Detailed Flow (RR01, RR02)
Actors: System · Bank · Payer (contacted only after all signature attempts in a bank submission fail)  ·  Screen: SCR-PAY-002
⚙️ 1 bank submission = one full round of signature attempts. The Bank Submissions counter stays at its current value while the system is trying signatures. It goes up by exactly +1 only when the round is done — whether a signature was approved or all failed. A round with 6 attempts counts the same as a round where the first signature succeeds: both = 1 bank submission.
1st bank submission: up to 6 signature attempts (5 drawn signatures, then the EID signature if all 5 fail).
2nd bank submission onwards: up to 5 attempts (drawn signatures only — no EID signature).
The payer is NOT contacted until all signature attempts in a bank submission fail. Every contact always includes the correction link.
ℹ️ Max Bank Submissions = max number of bank submissions allowed. Max Payer Reminders and Max Bank Submissions are system-triggered. Escalated is ops-only.

9Signatory Change Flow (RR14 — Signatory Not Authorised for Mandate Amount)
Actors: System · Current Payer · New Signatory · Bank  ·  Screen: SCR-PAY-006  ·  The existing mandate is updated — a new mandate is not created.
ℹ️ Forwarding the link is optional. Whether the new signatory fills the form on their own device or the same device, the screens and data fields are identical.
If the bank rejects again with RR14, the flow returns to the top of this workflow. A different rejection code routes to WF 1.
⚠️ All critical actions require confirmation dialogs before execution.
